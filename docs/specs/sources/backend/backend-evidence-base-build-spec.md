## 1. EB artefact & scope ✅

- EB is a single, **broad** capability producing one artefact.
- The artefact spans a **landscape ↔ synthesis depth axis**: shallow → an evidence *landscape* (corpus shape — the §3.3 metadata-grounded patterns, clusters and gaps); deep → adds a *synthesis* of what the evidence says (Tier-1 findings → grounded blocks). The deep artefact **contains** the landscape.
- Landscape and synthesis are **distinct, dependency-connected components**, not a pure gradation. They differ in output shape — scan-grounded shape content (patterns / clusters / gaps) vs source-grounded findings (claims with direction / strength) — so each is its own component (the §4 I/O test: an I/O-shape change is a component boundary, not a gradation). *This is a distinction in **production** and grounding mode, not a presentation boundary — both compose freely into user-facing sections (see §3).* The synthesis components **consume the landscape's selection scan** (§4 *scan first, extract second*): the clusters and coverage tell synthesis *where* to go deep. **Depth is a §5 gradation *over* the component chain** — how far down it a run goes — orchestrator-inferred from intent, surfaced as concrete scope, adjusted by the lighter / deeper nudge. Gradation governs which components fire; the components themselves are genuine structure. (This is the “a single notion spans gradation / component / capability” pattern the architecture note flags for scrutinise/red-team, §4.)
- Narrow, single-intervention deep analysis is **out of EB** — that is the **Impact** capability (question-relative analysis; the §4 evidence-vs-analysis line). EB stays broad by definition; depth is its only gradation.
- **Precise option resolution is out of EB.** EB groups interventions *descriptively* (corpus-grounded thematic clusters — what the evidence covers). Resolving those into a precise, canonical, comparable set of *named options* is decision-relative and defers to a future **Options Assessment** capability, which consumes EB's output + the findings layer. Same evidence-vs-analysis line as Impact / Transferability.

> **Flows back to the architecture note (framework-level):** EB-as-deliverable is broad and depth-graded along a landscape↔synthesis component chain — this partly pins the §4 *horizon-scan / Evidence-Base-as-deliverable theming* 🟡 (the EB artefact's broad shape). The theming **mechanics** remain open (below).

## 2. Component skeleton ✅

The skeleton runs from broad acquisition (the shallow / landscape terminus) through to grounded synthesis (the deep terminus); depth (§5) sets how far along it a run goes (§1). Tool wiring is captured per component as each lands.

**EB owns evidence assembly** ✅. Unlike analysis capabilities — which start *downstream* of an existing selection (VfM, Transferability scope to already-acquired documents) — assembling the evidence base broadly *is* EB's distinctive job. So its skeleton **includes the assembly components**, and **`search` egress originates from inside the EB run** (each call emitting its §9 governance event).

**First component — acquire / gather (the front edge)** ✅. EB opens by gathering a broad corpus via `search` over the configured evidence backends (OpenAlex, Overton), plus any uploaded corpus already present — at this point **metadata only** (title, abstract, metadata), **no full text**. Bounded by the **configured backends / trust classes** (the acquisition constraint, §5); the source/evidence policy's **use-face** — the citable-support bar, **flag-not-block**, *not* a retrieval or acquisition boundary — applies later, at characterise and synthesise (below). Breadth is **intent-derived**, not fixed. Full-text fetch + Tier-0 ingestion (snapshot / parse / segment / embed) does **not** happen here — it is **gated by screen** (below), so non-relevant documents never incur acquisition / parsing / embedding cost (the v2 efficiency). *Ingestion is not a tool* (§4); this component's verb is `search`.

**Second component — screen** ✅ *(now its own tool/verb, `screen`)*. A distinct, **recall-oriented** relevance filter run as a **per-document fan-out** (parallel over the gathered set, atomic to the durability engine — the retained §4 within-step fan-out). The dangerous failure for a broad scan is the false negative — a study filed under "homelessness prevention" wrongly dropped from a rough-sleeping scan. **v3.0 screens on metadata** — title + abstract, **degrading to title-only** where no abstract — and is **fail-open**: *"no abstract" must never behave like "not relevant."* It emits `is_relevant` + relevance `confidence` + a **`screen_basis`** flag (`title_abstract` | `title_only`) and a retryable **`screen_failed`** state distinct from not-relevant. Screening runs on the cheap `search` envelope, so non-relevant docs never incur full-text fetch (full Tier-0 ingestion stays gated post-screen). Adds the §4 escape hatch V2 lacked: **re-search when the screened base is too thin** rather than continuing regardless. *(V2 steer, C: its screen prompt was deliberately inclusive — keep that — but it had no re-search loop and gated on the boolean alone, never using the confidence score.)* **Confidence is load-bearing (light)** ✅: it feeds the thin-base re-search trigger (thin = too few *sufficiently-confident* relevant docs, not just a raw count) and flags / orders borderline inclusions — but is **never a hard exclusion cutoff** (preserving recall). Uses what V2 wasted, without sacrificing the recall posture. ⏸ The richer **tiered content peek** — exec-summary / headings / passage scan for poor-metadata grey lit (title/abstract is weak for grey literature) — is **deferred** to a seam, per the architecture note (§4; revision note part 8), which supersedes the earlier in-v3.0 tiered envelope.

**Third component — classify** ✅ *(distinct from appraise; its own tool `classify`)*. Cheap classification on the screened-in set, title + abstract + metadata, as a **per-document fan-out**. Classification (*what kind* of document) is a separate operation from appraisal (*how good*). It produces **two distinct things**:
- a single-valued **`primary_evidence_type`** — a **closed column** (the routing / appraisal key; a study has one primary design). **Carries V2's categories for v3.0 parity** (the rubric maps off them, no migration churn). V2's grey-lit categories are **coarse** ("Policy Guidance" and "Expert Opinion" conflate statutory guidance, strategy, think-tank output, commentary), so ⏸ **grey-lit category granularity is a deferred refinement** (splitting those primary types — with policy-team input, not invented now).
- proposed **methodological / structural tags** — the former "secondary modifiers" (mixed-methods, review-plus-primary, economic / qualitative / implementation-process component, policy-context). These are **open, inferred tags, not a closed column** *(review thread, revised)*: they're LLM-inferred (not deterministic), grey-lit variety is unbounded (a closed set would miss types), and their job is scoping / description — so they live in the **open tag layer** (open/extensible vocabulary, **seeded with the common modifiers**, **namespace-consolidated**), not a frozen column. This is *not* flat multi-label on the primary type; it's one closed routing key + open methodological tags (see the **Tag model** note below).

*(V2 steer, D: single-label "best-fit" into 9 categories.)* Note: in V2 the category also **routed extraction** (SR vs RCT workflow) — a synthesis-end concern, deferred to the extraction profile, not Tier-0.

**Fourth component — appraise (per-document only)** ✅. Cheap **document-level** quality tier, as a **per-document fan-out** (the `appraise` tool). It applies a **rubric** (document type + typed dimensions → quality tier, §4) — **not a fixed global hierarchy**. The rubric is **steerable, but default-first**: the orchestrator puts a **provisional default** rubric in the plan it first generates (inferred from domain / intent) — the user isn't asked to design or even specify one; they can **inspect and adjust** it (in plain language, which the orchestrator compiles; or directly, for advanced users) but needn't engage with it at all. Progressive disclosure (§1): the rubric is held in full but surfaced only on demand. The **rubric version travels with each appraisal** for provenance and reproducibility. *(V2 steer + anti-pattern, E: v2's rigid SR > RCT > observational ladder is exactly what users flagged — domains without RCTs cap out low, so good evidence reads as weak. The steerable rubric fixes that.)* **v3.0 is a single light pass:** a cheap tier from **metadata + title/abstract, primarily document-type-based** (≈ v2's evidence-strength stage carried forward), over all screened-in. ⏸ **Appraisal-improvement seam:** a fuller appraisal is deferred — a richer **full-text pass** (methods quality, risk-of-bias) gated to the **selected** subset (the *two-stage* shape the review proposed: light-all / full-selected, keeping a hundreds-of-docs scan affordable), **plus modifier-tag-driven dimensions** (reading component 3's methodological tags as new rubric dimensions via §4's extensible-typed-dimensions mechanism — an LLM / soft read, with the escape that any signal needing a *deterministic* read is promoted to a closed column/dimension). `appraise` is re-runnable, so the seam adds the second pass without a new component. ⏸ **Relative-to-feasible seam:** a richer tier normalised against the best evidence *achievable* for this kind of question (so observational can read "strong for this domain") — cross-document, edging into the deferred roll-up. The **cross-document roll-up** (max-across-qualifying, single-study caps, density cap) likewise stays **out of EB's appraise**, at the deferred v3.0 seam; EB appraises per document.

**Two-stage by cost** ✅ *(full pass = seam)*. v3.0 runs the **light** pass — this cheap metadata tier over *all* screened-in (Tier-0). A **full** pass — richer full-text appraisal (methods quality, risk-of-bias) — runs only on the **selected** subset (Tier-1, alongside extract; cited ⊆ selected), so a hundreds-of-docs scan never pays full appraisal on the long tail. `appraise` is re-runnable (§4), so this is two depths of one tool, not a new component. The light pass is v3.0 (v2-aligned); the full pass arrives with the appraisal-improvement seam.

**Full-text ingestion — gated by screen, built for all screened-in** ✅. screen / classify / appraise run on the cheap screening envelope — metadata (title/abstract, degrading to title-only; component 2). *After* them, full text is fetched and fully Tier-0-ingested (snapshot → parse → segment → embed) **for the entire screened-in set** — not just the subset `select` will deep-extract. This is the **cheap, shared substrate**: the corpus (text + vectors) that downstream capabilities (Impact, Transferability, VfM, Options Assessment), retrieval and Private Q&A reuse — so it is built at the *relevant* level and amortised, while only the expensive **Tier-1 extraction** (component 7) is further gated by `select`. This maps onto the architecture's Tier-0 (cheap, shared) / Tier-1 (scoped, dear) split. Full-text fetch is **egress**, but mechanical execution of the governed `search` — captured on the **telemetry plane** with a run-record summary on the canonical side (§8), *not* a per-document event on the audit log. *(Decided post-screen over post-select: the relevant corpus is the reusable Evidence Base, useful to downstream synthesis even where EB itself doesn't deep-extract a doc. Consequence: even a shallow landscape run builds the full-text corpus.* ⏸ *budget cap + lazy vectorisation for very large relevant sets — a possible later refinement.)*

**Fifth component — landscape characterisation (shallow terminus)** ✅. Produces the corpus-shape blocks, in two parts:
- *Coverage / patterns over metadata* — deterministic distributions and gaps over Tier-0 columns (study-type, geography, recency, population, category). The §3.3 metadata-grounded patterns; richer gap detection than V2's two-item list (I). **Source/evidence policy is flag-not-block here** (use-face, §5 — not a retrieval boundary): EB reads and counts *all* relevant in-corpus evidence, so coverage/gaps reflect what **exists**, with below-policy evidence **present-but-flagged, never absent** (no false gaps). When the user has supplied a policy, characterise computes **two coverage views** — the **overall** landscape and the **policy-filtered ("well-evidenced")** landscape (coverage over above-bar evidence only) — side by side, the **delta** showing where the evidence base thins once the user's citable bar is applied. This is descriptive **dual-view coverage** (cheap, deterministic), *not* the deferred weighted-strength roll-up. These shallow gaps rest on the **screened base** (*Gap provenance & coverage base*) — the whole relevant corpus — so they never read `not_selected` / `not_extracted` as absence.
- *Thematic shape — graded by depth.* At the shallow landscape: cheap **topic-level clustering** over abstract / document embeddings (the §4 `cluster` tool, reusing Tier-0 embeddings), lightly LLM-labelled per cluster — cost scales with cluster count, not corpus size. Honest about what's cheaply knowable: coverage + broad topic shape, not facet-level themes. The per-cluster topic labels persist as **topic/theme tags** (per-doc scoping handles); the run's cluster **grouping** stays run-local — distinct artefacts (see Tag model).

**Facet-level thematic grouping is a *deeper* product**, not part of the shallow terminus. It groups over **extracted concepts** (the `query-findings` arm) on an **intent-derived facet** (interventions / outcomes / populations / mechanisms — *not* V2's fixed four), and is its own component — **group** (eighth, below), between extract and synthesise. *(V2 steer, G: V2's good themes were a post-extraction product (`create_canonical_concepts` over extractions) and rigid — fixed facets + always-extract. V3 makes the facet intent-derived and pays for deep grouping only when depth warrants.)*

> **Pins the §4 theming 🟡 (flows back to the architecture note):** EB-as-deliverable theming mechanics resolved — metadata patterns + topic clustering at the shallow landscape; intent-derived facet grouping over extracted concepts deeper.

**Tag model (cross-cutting)** ✅. Tags are the **open, inferred, multi-valued labelling layer** the system uses for **scoping** — how a sub-agent points at a subset of the corpus (the primary *why*; the usage-proposes hybrid, §3, is one growth path, not the main one). Created by the **capabilities that read the documents** — `classify` proposes **methodological / structural** tags, characterise proposes **topic / theme** tags — *not* by the orchestrator, which only **keeps the namespace consistent** (so one agent's "Housing" is another's), no benefit to it owning the writes. Each tag carries its **type** (topic/theme · methodological/structural · organisational/line-of-work · …, an **open, extensible** type-set), held on the namespace entry — to drive type-aware scoping, within-type consolidation and capability relevance — kept light (label, type, proposing-capability), consistent with §3's "nothing hangs off a tag". Fragmentation ("economic component" vs "cost analysis") degrades **gracefully**: scoping is a **soft prior that widens via hybrid retrieval** (§3.1), whose dense arm bridges synonymous tags — so namespace consolidation buys *precision*, not *recall*. *(Framework-level — flows back to §3.3.)*

**Sixth component — select (deep terminus opens)** ✅. Chooses the subset for Tier-1 extraction — a clean departure from V2, which had **no** select step (it extracted the whole screened set — the monolith, M2). **Coverage-aware stratified selection over the characterisation clusters**, breadth-adaptive: the landscape step has already *measured* breadth (cluster count and spread), so selection needs no separate broad/narrow mode — it stratifies across whatever clusters exist, and depth (§5) sets how deep to go *per* cluster. Broad, many-topic corpus → many clusters → spread thinner to preserve breadth; narrow scope → few clusters → deeper in each. This guards the architecture's warning against horizon scans collapsing onto a narrow top-k. *(The landscape clusters thus do double duty: corpus shape **and** the stratification basis for selection.)* **Realised as a shared tool** (`select`): a strategy-parameterised verb — *(candidate set, cheap signals, strategy, budget) → chosen subset + selection rationale* — with EB's coverage-aware stratified-over-clusters as one strategy (Transferability's dependency-scoping another). Rationale is captured **uniformly** because *which* documents are deep-extracted shapes coverage / emphasis (§6 substance-relevant). Framework-level → flows back to the architecture note.

**Selection signals (cheap, pre-extract)** ✅ *(review-enriched)*. Cluster coverage is the breadth *skeleton*, not the whole basis. `select` combines, over **cheap signals only**: **relevance** to intent (embeddings / screening), **recency**, **origin / upload-priority** (uploads and user-nominated sources favoured), the **light appraisal tier**, and **must-includes** (user-nominated / official docs as a **hard-include that bypasses the budget** — the one hard rule in an otherwise soft, weighted scan). The **source/evidence policy tilts but never gates** — a soft prior preferring above-bar material, *never* a hard exclude (flag-not-block, comment-1 consistency), else selection would re-manufacture the false gaps characterise guards against. **Diversity is reliable only on cheaply-known dimensions** — topic **clusters** (the stratifier) plus the clean metadata above. **Publication country** *is* cheap metadata — a usable but rough geographic signal — but the **study / intervention geography** (what the evidence is actually *about*) can differ and lives in the text, and **population and intervention-type aren't metadata at all** (they need extraction). So selection can stratify roughly on publication country, but diversity on **study-geography / population / intervention-type** is cluster-approximated and properly a **post-extraction** property; rough abstract-inferred tags are a possible cheap extension — flagged, not baked. **Rationale is bidirectional**: it records both what was selected (why) and what was *not* (aggregate exclusion reasons + notable flagged exclusions), since selection shapes emphasis even in a descriptive artefact — which is also why selection is EB's pre-declared **deepening-selection steer-point** (§4): the rationale logged here is exactly what that steer-point reads to evaluate its escalation triggers.

**Seventh component — extract (Tier-1)** ✅. Per selected document, extracts `intervention_outcome_finding` records. **Grain:** a finding is **one (intervention, outcome, effect) claim grounded in a single source** — intervention, outcome **and study population** carried as **source-named references** (groupable / canonicalisable downstream, *not* baked-in canonical entities, per §1's Options Assessment boundary). This is V2's flat result-row grain (`ResultItem` linked by `intervention_idx`, no separate outcome entity — F) lifted to a first-class reusable record.

**Field set — the line is source-groundability.** The base finding holds **what the source reports**: effect direction; effect size + type; uncertainty (CI / SE); p-value; study-design / sample metadata (design, N, k, I²); the **study population** (source-named — e.g. "homeless adults in temporary accommodation" — a base field because it is source-groundable context and the effect is *for* that population, enabling deep group-by-population); the **descriptive causality label** (causality-by-design — e.g. RCT → attributable, readable from the method); and the **primacy / prevalence-only** flags. **Question-relative judgements stay out, as analysis enrichment** layered by Impact / VfM: normalised magnitude (the *categorical* judgement, not the raw effect size), causal *weighting*, and is-beneficial (which needs a desired direction). This keeps the finding a **reusable evidence record**, not one pre-committed to a single analysis — the separation V2 lacked (it packed both into one `ResultItem` feeding Impact, F).

> **Flows back to the architecture note:** `intervention_outcome_finding` is a reusable findings-layer schema (§4), so its grain and field set are framework-level and recorded back there; EB's *extraction profile* (its commit to extract these base fields over the selected subset) is the EB-specific part.

**v3.0 deep-synthesis scope — and the second-schema seam** ✅ *(review-prompted)*. Deep grounded synthesis in v3.0 is centred on **intervention–outcome(–population) evidence** — what `intervention_outcome_finding` captures. The **shallow landscape covers any facet** (mechanisms, barriers, delivery models, populations) via topic clusters / tags / metadata — broad shape is facet-agnostic — but **deep grounded synthesis is schema-bound**. ⏸ **`implementation_context_finding` seam:** a *different evidence kind* — mechanisms, barriers, implementation conditions, delivery / process findings (the "how / why / under what conditions", not "what effect") — is a **deferred second schema**, named not built. **Cross-schema linkage is reference-mediated:** the seam schema must carry the **same source-named reference vocabulary** (intervention / outcome / population / setting), so findings of both kinds naming the same intervention are joined by the *existing* reference-clustering (`group`), not by new link objects — and synthesis can span them (effect + mechanism / barrier), each finding still single-source-grounded, the two evidence kinds kept **related-but-distinct** (never a barrier blended into an effect claim).

**Eighth component — group (facet-level theming)** ✅. A distinct component between extract and synthesise (not folded into the write-up), matching §4's "thematic analysis stays a component, per-capability." It groups the extracted findings on the **intent-derived facet** — in v3.0 the facets the schema supports: **interventions / outcomes / populations** (the source-named references), *not* V2's fixed four; **mechanisms / barriers / implementation conditions stay landscape-only** (characterise) until the `implementation_context_finding` seam lands, when they become deep facets joined cross-schema by shared references — via `cluster` over finding records / dimension values and `query-findings` (§4). This is the **second clustering** in the chain — the first, at characterise, is topic-level over abstracts; this one is facet-level over extracted concepts — and giving it its own module keeps that distinction clean. *(V2 steer, G: the post-extraction theming that produced v2's good themes, here de-rigidified and intent-driven.)*

**Ninth component — synthesise (deep terminus)** ✅. Over the **grouped** findings, **per group produce a grounded block** reporting what the findings show. **Descriptive**, surfacing the direction-spread (e.g. "5 of 7 findings positive on tenancy, two null") — V2's `effect_consensus` / positive-negative-null counts are the descriptive steer (G / K). Each claim grounded via the settled §4 mechanism (deterministic quote-presence + LLM judge; Unsupported / mis-cited a real state), *not* V2's permissive post-hoc fuzzy matching (anti-pattern, H / M4). The source/evidence policy's citable bar is applied **flag-not-block**: below-bar support is **flagged** (weakly-grounded / below-policy), not hidden or silently dropped. Deep "gaps" here rest on the **selected / extracted base** (*Gap provenance & coverage base*) and are **base-labelled, never promoted to corpus absence** — the shallow landscape is the check on them. **Consensus seam ⏸:** the *weighted* verdict — consensus-scored, strength-weighted ("the evidence supports X at strength Y") — is a roll-up, deferred to the same v3.0 seam as the aggregate appraisal (the divided-evidence / weighted-strength machinery the architecture already pushed there). Its **candidate mechanism** is the **graph-structured synthesis seam** (arch note §4): query-time multi-hop pattern / contradiction-location over the findings graph, **run-local first, never a global KG**, gated on an entity-resolution-quality bar.

**Skeleton (complete):** acquire → screen → classify → appraise → **characterise** *(shallow terminus)* → select → extract → **group** → **synthesise** *(deep terminus)*. Depth (§5) sets how far down the chain a run goes (§1): the shallow terminus is the landscape, the deep terminus the synthesis. screen / classify / appraise run as per-document fan-out. **Full-text ingestion is gated post-screen** (cheap shared substrate, all screened-in); **Tier-1 extraction is gated by `select`** (the scoped, expensive step).

**Cluster persistence** ✅: clusters / groups (from characterise and group) are **run-local execution state**, not information-layer objects — checkpointed for resume (§9) and reflected in the durable artefact blocks, but never promoted to canonical, queryable state. They are a **recomputable grouping** over embeddings / findings (corpus shape is recomputable, §4); the findings layer holds the findings. No v3.0 consumer needs persisted clusters (Options Assessment does its own canonical grouping, §1).

**Derived-claim provenance — gap base & pattern grades (cross-cutting)** ✅ *(review thread — the central trust rule)*. EB's most consequential claim is an *absence* ("little evidence exists on X"), so the design must make it structurally impossible for a pipeline artefact to masquerade as a corpus fact. The select→extract gating is what makes this acute: extraction is gated to the **selected subset**, so the extracted finding set is a *strict subset* of the relevant corpus, and any absence read off extracted findings is relative to *what EB chose to extract*, not to the corpus. The rule (framework-level, §4):

- **Every gap / absence claim carries its coverage base** as a required field — the pipeline ladder **attempted-search → acquired → screened → selected → extracted**. Each rung narrows; each narrowing can manufacture a false absence.
- **Only `searched_and_absent` over an adequately-searched base licenses an absence claim.** `not_selected` (doc screened-in but not chosen — the gap select creates), `not_extracted`, `extraction_failed` and `unclear` **never** do. A reported null is a *finding*, not a gap; a silence is *coverage*.
- **Even `searched_and_absent` is bounded by acquisition scope** (§5): absence is "absent from the searched space" (configured backends / trust classes), never absolute — corpus-level absence carries a search-adequacy caveat.
- **Shallow vs deep base, from the depth axis:** characterise's **shallow** coverage rests on the **screened** base (the whole relevant corpus — flag-not-block, so no false gaps); synthesise's **deep** coverage rests on the **selected / extracted** base (a subset), must be **base-labelled**, and is **never promoted to corpus absence**. The shallow landscape is the structural check on a deep absence: nothing on X in extracted findings *but* X-relevant docs in the screened-base landscape ⇒ surfaced as `not_selected`, not "little evidence exists".

The same discipline applies to *patterns*, not only gaps. **"Pattern" is not one thing — it spans three grades, never to be conflated**, each carrying different authority:

1. **Deterministic metadata patterns** — counts / distributions over Tier-0 columns. Facts: exactly reproducible, profile-independent, over the whole screened base. *Hardest grade.*
2. **Finding-query patterns** — counts / direction-spreads over extracted findings. Deterministic *given the recorded (finding-set, coverage-state, extraction-profile)*, but extraction-coverage / profile dependent — so they carry that provenance and are **not metadata-grade** (§3.3 leaves their grade and roll-up relationship ❓ open). *Middle grade.*
3. **Thematic clustering** — the `cluster` groupings (topic-level at characterise, facet-level at `group`), LLM-labelled. The grouping is a modelling choice (embedding + algorithm + parameters) and the labels are generative, so it is an **interpretive shape, not a count** — recomputable, never a deterministic fact. *Softest grade* — and facet grouping at `group`, being clustering *over extracted findings*, carries both the clustering softness **and** the extraction dependency.

## 3. Output structure ✅

**Sections, not blocks.** The user-facing artefact is a set of report-like **sections**; **blocks** and their addressable units (architecture note §3) are the substrate beneath. Grounding is a **per-unit** property — scan-grounded for a pattern / cluster / gap, source-grounded for a finding-claim — so a single section **mixes grounding modes freely** (e.g. "evidence concentrates in urban US settings [pattern], strong on tenancy sustainment [grounded, cited], a gap in rural provision [gap]"). The characterise / synthesise split is about **production**, not presentation.

**EB declares little; the orchestrator composes.** EB fixes only that the artefact carries an **artefact summary** (the settled §4 artefact-level summary — *citation-free navigation*, anchored to detail, judge-verified, **outside the grounding economy** — deliberately **not** called "key findings", since a citation-free device read as the evidential headline would undermine grounding) and exposes two **content kinds**: landscape *shape* (patterns / clusters / gaps) and grounded *findings*. When a **headline evidence claim** is presented it is a **grounded key-findings block** — a *grounded* content form carrying its headline at the appropriate grade (source-cited for a synthesis headline, metadata-grounded for a landscape headline), **never** the citation-free summary; **conditional-required** (present whenever a headline claim is made, absent on a pure-navigation / thin run). The **orchestrator composes the actual sections** — how many, around what facets, in what order — from the user's intent. "Synthesis" is therefore **multiple sections** (typically organised around the facet grouping — e.g. one per intervention family), not one.

**Basic convention (soft default):** artefact summary (navigation) → [grounded key-findings block, *if* headline claims] → landscape → grounded synthesis — depth-ordered, general-to-specific. **Production ≠ presentation:** this is the *presentation* order. In *production* the grounded key-findings block is created **last** — it is a headline condensation of what synthesis discovers, so it depends on synthesis — and the artefact summary is likewise a late display-layer rendering; both are shown near the top but produced after the content they head. The orchestrator follows this by default and adapts to intent; it is a convention, not a rigid template. *(V2 steer, H: its briefing was a fixed frame with 0–2 dynamic sections — the fixed-frame-with-dynamic-middle is a reasonable precedent. EB departs from V2's **decision-oriented** frame (… → core_answer → recommendations): EB is evidence-descriptive, with no recommendations / decision-answer section, per §1.)*

## 4. Check-in points ✅

EB does **not** define its own check-in policy — check-in **frequency** is the user-set §6 **steering mode** (Minimal / Moderate / Frequent). The landscape → synthesis crossing is therefore a **mode-governed steer-point**, not an EB gate: Frequent pauses there, Moderate pauses when the scope choice is important, Minimal flows through (logging / flagging).

**EB declares no unconditional input gate — but it does pre-declare one emphasis-shaping steer-point.** Unlike a capability with a known conclusion-shaping *input* (VfM's discount rate, §4 / §6), EB is **descriptive** — it renders no verdict, recommendation or option-framing (§1) — so it forces no unconditional input-confirmation pause. But its **deepening selection** (which clusters / documents go to deep extraction) is *not* an unanticipated residual: it is a **known, recurring, emphasis-shaping judgement** (which documents are deep-extracted shapes coverage / emphasis, §6-substance — component 6). Leaving a known judgement to the §6 **residual** — the catch-all for the *unanticipated* — was a category error; following §6's *resolve-structurally-not-by-runtime-judgement* pattern, EB instead **pre-declares "deepening selection" as a named steer-point with explicit escalation triggers** (§6 supports declared triggers, not only mode-governed frequency):

- **Always** log the selection rationale — the bidirectional rationale already captured (component 6); the steer-point *reads* it.
- **Escalate above the steering-mode baseline** when a trigger fires, each a computable proxy for *materially shifts emphasis*: the selected subset **excludes a large / high-priority / user-nominated cluster** (cluster sizes + must-includes); the **evidence base is thin** (the screen thin-base trigger); the **policy can be supported only by below-policy sources** (a near-empty policy-filtered "well-evidenced" landscape — the characterise dual-view delta). The strongest — a **user-nominated** cluster dropped (violates expressed intent), or a policy **unmeetable above-bar** — escalate hardest, surfacing **even in Minimal**; softer ones flag-and-pause per mode.
- **Otherwise route by steering mode**, as for the landscape → synthesis crossing.

This **narrows the residual** to genuinely unanticipated emphasis shifts rather than abandoning it. *(Still no unconditional always-pause gate; and substance can never be silenced by the frequency dial — §6 hard constraint.)*
