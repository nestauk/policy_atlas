## The findings as delivered

Reviewed current branch head `9a834336`; no files were changed and no tests/builds were run.

1. **Blocker — N7 / D2 / S3.** Evidence: `contract.md:85,89-90,175`; `web-api.md:718-725`; `ADR 0027:46-56`; `reducer.ts:14-26`. Risk: append-only ephemeral deltas cannot reconstruct a mid-section reconnect. Replay restores only the skeleton and `section_started`; subsequent suffix deltas append to an empty draft, producing truncated prose until completion. The frames therefore are state-bearing despite the contract saying otherwise. Fix: send cumulative prose snapshots that replace the draft, including a current snapshot on reconnect, or make deltas durable. Test disconnect/reload after N chunks, subsequent chunks, process restart, and fallback.

2. **Blocker — N22 / G1 / S4.** Evidence: `contract.md:96,190,280-281,308`; `api/contract/read_models.py:1067-1110`; `repository.py:4009-4027`. Risk: “existing `LonglistOut` plus the flag” cannot honestly represent “no result”: `run_id`, `plan_version`, `counts`, `shortlist`, and other result-derived fields are required. Implementation must fabricate values, widen more fields than G1 approves, or fail validation. Fix: contract an explicit discriminated building shape, or preferably use the annex’s simpler alternative—a separate task-scoped options read—without invented result identifiers. List its complete schema in G1.

3. **Blocker — N9 / G1 / S4.** Evidence: `contract.md:54,177,280-281,308`; `web-api.md:4,21-24,308-332`; `task_agent.py:948-960`; `conversations.py:653-775`. Risk: changing an existing JSON POST into NDJSON is breaking, not additive. The contract also omits media type, complete event union, terminal failure semantics, idempotent replay, pre-header errors, and whether work survives client disconnect. Fix: preserve the JSON representation through content negotiation or add an additive streaming representation. Pin the chat precedent exactly: reservation/auth before headers, provider-neutral events, exactly one terminal event, completed retry as one terminal event, and worker completion independent of disconnect.

4. **Blocker — N25 / N1 / N5 / D13.** Evidence: `contract.md:99,169,173,193,251-252,359-360`; `rubric.md:94-97`; `exp-event-gaps-and-bands.md:56-74`; `tracing.py:276-315`. Risk: “no silent gap over 30 s” is unattainable as contracted. Hooks emit only before/after calls, while the UI deliberately stops moving after 1.5 s and waits 120 s before changing text. Long in-flight calls can therefore create 30–120 s gaps. It is also not measurable from `stage_walls.py`: ticks and queue drops are not durable, no drop counter is specified, and acceptance asks only post-change staging although N25 requires staging before/after. Fix: add a real in-flight heartbeat below 30 s or narrow the target explicitly. Specify a tick recorder, drop counter, clock boundaries, saved-result identifiers, “healthy” criteria, and consistent laptop/staging sampling.

5. **Blocker — Status / contract gate.** Evidence: `contract.md:6-14`; `plan.md:1-14`; `.claude/skills/task-cycle-design/SKILL.md:106-117`. Risk: a plan was committed while the contract-stage adversarial review remained in progress, although this review is required before planning. Material findings can no longer shape a clean plan handoff. Fix: stop plan confirmation, adjudicate this review, reopen owner approval for material contract changes, then regenerate or revise the plan from the approved contract.

6. **Material — N1 / N2 / “honest count.”** Evidence: `contract.md:87,121-124,169-170`; `tracing.py:230-240`. Risk: N1 counts completed model calls while N2’s totals count documents, batches, options, or sections. Retries and stages with multiple calls per item can make `done > total` or compare unlike units. The generic wrapper also does not know which item completed. Fix: use wrapper hooks only for fixed activity verbs/call liveness. Publish item/batch progress from loop completion callbacks, with an explicit unit per counter.

7. **Material — N5.** Evidence: `contract.md:173`; `sse.py:439-466`; `runner.py:5956-5967,6014-6034`. Risk: `component.completed` is committed before `component.timing`; a live SSE poll can project `seconds=null`, and the later timing event produces no frame to repair it. Merged rows also lack timing semantics: search+screen and classify+appraise each have multiple component durations. Fix: put wall time in the terminal event before it becomes observable, or emit a durable timing update. Define merged-row time as wall interval, sum, or named constituent and test live-tail ordering, not replay alone.

8. **Material — N15 / N17 / G1.** Evidence: `contract.md:183,185,280,308`; `stage_vocabulary.py:1-8,19-56`; `common.py:383-393`. Risk: `TaskOut.active_run.stage` supplies only a key, yet N17 deletes client label maps and requires server-owned wording. The task list cannot display the label without recreating copy locally. Additionally, `active_run` currently selects children, so a scoping task can show a child’s `acquire` instead of the parent’s `option_searches`. Fix: add a server-supplied `stage_label`/presentation field to G1 and derive it from the active parent walk, with child-concurrency tests.

9. **Material — N4 / D2.** Evidence: `contract.md:85-86,172,204-208`; `liveness.py:44-50,70-94`; `sse.py:643-688`. Risk: last ticks are keyed only by task and stage, with no run ownership, expiry, terminal clearing, or global bound. A later run can receive stale activity from an earlier run; concurrent child activity can overwrite parent activity; retained task entries can grow indefinitely. Fix: associate cached ticks internally with the current run, clear them on stage/run terminal and new-run start, add TTL/global bounds, and test reruns and parent/child concurrency.

10. **Material — N3 / Owner ruling 4 / public-private boundary.** Evidence: `contract.md:171,261-262,320-323`; `web-api.md:21-23,715-720`; `structured-output-streaming.md:50-54`. Risk: “derived from the task question” does not mean non-identifying. Questions can contain names, sensitive facts, or injected instructions; the model can elaborate them. Verbatim query text also turns internal model output into a Hyrum dependency and is harder to moderate while streaming. Fix: use fixed activity text, or at minimum normalize, length-bound, control-character-strip and privacy-review the query. Correct the claim that it can never contain identifying data.

11. **Material — N6 / N8 / ADR 0015.** Evidence: `contract.md:174-176,334-335`; `ADR 0015:39-57`; `SectionProseWire`, `section_prompt.py:241-253`; `synthesise.py:4260-4303`. Risk: raw prose is shown before span binding, validation, the unspanned-assertion scan, or grounding judgment. The annex gives it no explicit draft/unverified accessibility state, and fallback after partial output has no reset rule. Escaped Unicode and arbitrary chunk boundaries can also make displayed prose differ from parsed prose. Fix: pin a visible and accessible “writing/checking” draft state, terminal drafted-not-final behavior, partial-reset behavior on fallback, and tests proving accumulated decoded prose equals `parsed.prose` across escapes/chunk splits before the unchanged claim path runs.

12. **Material — N18 / N19 / N26.** Evidence: `options-scoping/capability.md:162-170,218-220,535-550`; `contract.md:186-194`; `rubric.md:76-100`. Risk: no acceptance journey pins the mandatory baseline pause and reconfirmation before suggestions. A cold implementer can satisfy the named UI tests while allowing the longlist/provisional read before the Tier-3 product gate is resolved. Fix: add a scoping journey asserting baseline run → durable pause → answerable gate → no suggested/provisional rows before confirmation → continuation → suggest/longlist.

13. **Material — N23.** Evidence: `contract.md:191`; `reducer.ts:28-33,68-88,117-153`; `useRunStream.tsx:118-165`; `runs.py:353-386`. Risk: storing child stage frames by walk ID still does not atomically map the walk to an option. `option_id` exists only on a separate runs read, so frame arrival and query refresh can race. The proposed store is heavier than the display need. Fix: either define the join/hydration sequencing and pending state, or simplify by returning each option’s child status/count in the provisional longlist read and refreshing that read on child status frames.

14. **Material — N22 security boundary.** Evidence: `longlist.py:80-91`; `read_models.py:37-43`; `repository.py:3375-3386`; `contract.md:190`. Risk: the route currently admits both authenticated readable and public-task readers. Returning unfinished suggestions earlier than today changes anonymous/public exposure, but the contract neither approves that semantic nor tests cross-tenant isolation. Fix: decide explicitly whether building rows use the existing public read grade or owner/member-only access. Add tests for public tasks, private cross-tenant indistinguishable 404s, and strict `task_id` scoping.
