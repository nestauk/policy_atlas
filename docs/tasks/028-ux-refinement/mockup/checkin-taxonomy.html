P2 as the theme-review moment

Theme mapping (characterise) runs before P2, so the themes exist when it pauses — P2 already carries "re-characterise with guidance". What the proposal adds: the card shows the theme map (names + document counts — read-model data we have), the re-map option covers both plain regenerate and custom instructions, and ✎ rename lets you fix a theme's name without rerunning anything. Rename is the one genuinely new capability here (a durable edit to the theme record that everything downstream then uses — new delta + audit event, gate-listed if ruled in).

Options unchanged: deepen · rescope filters · guide queries · accept and continue · stop.
P4 "How should the report be organised?" — as proposed · edit sections · emphasise stronger evidence · regroup (coarser/finer · guided). Already one subject. Copy polish only (kills the "(D8)"/"(B3)" leaks).

The open question: should P2 and P3 both pause by default?

In moderate (default) mode both pause on every run — two stops around one component. Option: P2 becomes fired-only in moderate (it pauses only when its coverage triggers fire — thin themes, heavy screen-outs), so a routine run has one reading-list stop; a problematic one still gets both.
