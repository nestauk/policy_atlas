**Simpler shape offered by the reviewer:** split into (A) timeouts with per-attempt logging,
widths, compiled bytecode, the pgvector write column and two in-process fixes (reserve fetch
bytes by Content-Length; embed each document as it is parsed); (B) queued fetch and parse with
embedding kept in the stage; (C) SQL retrieval after a synthetic-corpus parity test. The lead's
view: the owner prefers one consolidated slice and cuts; the plan orders its phases A → B → C
so each lands and is measured on its own. **Owner** decides the shape.

**Checked and found sound by the reviewer:** `queued` passes both check constraints; READ
COMMITTED lets the poll see other processes' commits; both embedding profiles are 1,536 wide;
lexical tokens are ASCII-only so SQL reproduces them; existing unique indexes support the
snapshot → chunk → unit join; Aurora 17.7 ships pgvector 0.8.0 (the migration's user must be
able to create the extension: verify); the parse worker uses `Process` and `Pipe` under
forkserver, so it should run on Lambda (verify under the emulator); SSE ticks are ephemeral so
late flips cannot corrupt replay; private subnets plus fck-nat give egress.

**Not judgeable from the files:** staging and prod `chunk_embedding` row counts; the account's
real Lambda concurrency and memory limits; whether staging's `DATABASE_URL` is the master user.
