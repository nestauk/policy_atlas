Screening experiments

Screening is the step that reads the title and abstract of each search result and decides whether to keep it. We tested this step against decisions made by human reviewers. A cheaper language model, with a revised prompt and each review's inclusion criteria, kept more of the relevant studies than the setting we use today, and cost about a fifth as much. It also did clearly better than methods that do not use a language model. The experiments took one day and cost about $9.

Main results

  1. The cheaper model is at least as good. gpt-5.6-luna kept as many relevant studies as today's model, gpt-5.4-mini, or more, in every comparison. It costs about a quarter as much per call. gpt-5.4-mini does no reasoning before it answers. gpt-5.6-luna does a little.
  2. Today's prompt handles inclusion criteria badly. The app adds a plan's inclusion criteria below the research question. In our tests, adding each review's published criteria lowered recall by 4 to 7 points. Today's prompt does not tell the model how to use criteria, so the model treated every criterion as a strict rule. It dropped studies because of details that a reader can only check in the full paper, such as the study design.
  3. Three changes to the prompt fixed this. The new prompt says that a criterion is a reason to drop a study only when the abstract clearly contradicts it. It says that a study about the right subject is kept even if one detail differs. If the user names a population, a clearly different population is dropped and a related population is kept. With the criteria included, recall rose from 0.854 (today's model and prompt) to 0.917. This is the final setting: it uses the criteria.
  4. The result holds on the full test set. With the final setting (Luna, new prompt, criteria included), recall was 0.900 on 2,949 documents. The best method without a language model reached 0.799 when it kept the same number of documents. The difference was largest for the development-policy questions from 3ie (0.884 against 0.750). Precision on SYNERGY was 0.688 for the language model and 0.633 for the best other method.
  5. Asking the model three times adds little. Today the model answers three times for each document, and the majority answer counts. This adds 0.7 points of recall compared with one answer. A cheaper rule adds 2.4 points: ask once, and ask a second time only if the first answer is "drop".

Ground truth

For each test, the model gets a research question and the title and abstract of one study. It answers "keep" or "drop". To score these answers, we need cases where the correct answer is known. Published systematic reviews and evidence gap maps provide them. Their authors decided, study by study, which studies to include. We give the model the same question and study, and count how often it agrees with the authors.

How we add the criteria

Each question can also carry the review's own inclusion criteria. A script copies them from the published source, in the same way as the titles, so no language model writes them. The source differs by dataset:

  • Cochrane (CSMeD): the "Objectives" section of the review's abstract.
  • SYNERGY: the eligibility criteria that SYNERGY quotes from each review paper, one criterion per line.
  • 3ie: the map's own list of intervention groups and outcome groups. Two maps (climate and anaemia) do not publish this list in a form we can read, so they have no criteria.

The criteria are added below the question by the app's own code, under the heading "Additional screening criteria". This is exactly what the app does when a plan includes screening criteria. The app accepts at most 2,000 characters in total and 1,000 per criterion. A longer criterion is split into sentences, and if the total is still too long the last criteria are left out. This happened for one review. For example, the question above is followed by six criteria, starting with: "Randomized clinical trials were included that examined effects of CBT (ie, any therapy with cognitive restructuring and/or a behavioral therapy, such as exposure, as core component)…"

The 30 questions come from three public sources, 10 from each. The meaning of a "drop" answer is different in each source. This affects what each source can tell us.

We used two test sets. The small set has 288 documents, and half of them should be kept. One run on it costs less than $1, so we used it to try ideas. The full set has 2,949 documents, and a third of them should be kept. We used it to confirm the best setting. The questions are the published titles. A script copied them from the sources, so no language model wrote them. Every experiment used the app's own screening code and changed only one setting at a time.

Limits of this test. In real search results, only a few per cent of documents are relevant. Here, a third to a half are. So precision in these tests is much higher than it will be in the app. Most of the "drop" studies are easy to reject: for the anxiety question above, they include studies of knee injuries and vertigo. Two thirds of the questions are about health. The test sets have no full texts, so the second screening step, which reads the full paper, is not tested. Recall is the most reliable number here.

Do we need to ask the model three times?

Today the model answers three times for each document, and the document is kept if at least two answers say "keep". We saved all three answers in every run. So we could test other rules on the same answers, without making new calls to the model.

A majority vote corrects a wrong "keep" as often as a wrong "drop". But for screening, a wrong "drop" is the worse mistake, because the study is lost. A wrong "keep" is less serious, because the second step reads the full paper and can still drop it. So it makes sense to ask again only when the first answer is "drop".

Precision is the share of kept documents that are relevant. F1 is a score that weighs precision and recall equally. F2 counts recall twice as much as precision. The rules differ by about one point on F1 and F2. Each rule gives up a little precision for a little recall. The majority vote has the best precision and F1. The rules that keep more have the best F2. F2 is the better guide for this step, because a wrongly dropped study is the worse mistake.

There is one good reason to ask more than once: consistency. If we ran the screen twice with one answer each time, about 5% of documents would get a different decision. A published study found 8% with a similar model. Asking again after a "drop" reduces the risk that matters most, which is losing a relevant study.

What did not work

A shorter promptWe kept the same rules but used 59% fewer words. Recall fell by 3 points with both models. The models stopped answering "unsure". The cost saving was small, and there was no saving with Luna, because short prompts do not get the discount for repeated text.
Adding criteria to today's promptWith today's prompt, adding the published inclusion criteria lowered recall by 4 to 7 points. The models dropped studies because of the study design, the data source or the comparison group, which an abstract rarely shows. The app adds a plan's criteria to today's prompt in the same way. The new prompt fixes this, so the final setting keeps the criteria.
Asking again when the model is unsureThe model reports a confidence score with each answer. It gave scores of 0.8 to 0.99 to its wrong "drop" answers, the same as to its correct ones. So a rule based on this score would not catch the mistakes.
Keyword search instead of a modelBM25 was only a little better than random choice on the small test set. Combining it with embedding similarity made the result worse than embedding similarity alone.

What we recommend

  1. Switch screening to gpt-5.6-luna with the new prompt (screen_v4), and pass the plan's criteria to it.
  2. Replace the majority of three with "after a drop, ask once more". First, confirm the result with one real run on the full test set.
  3. Before the switch, test on real search results. Label a small sample of real search results by hand. Check how many extra documents are kept and what the second step does with them.
