# Agent protocol

- Use the commands in the `Makefile`. `make verify` is the green bar; `make verify-fast`
  (backend) and `make frontend-verify-fast` (frontend) gate intermediate commits.
- For non-trivial work, plan before editing. The per-slice lifecycle is the `task-cycle`
  skill (`.claude/skills/task-cycle/`), tiered by risk.
- Write Google-style docstrings (`Args:`/`Returns:`/`Raises:` sections) for public modules,
  classes and functions; keep them concise. Trivial helpers and test functions need none.
- Use `docs/specs/` for product and system intent — **living intent, not golden**. If building
  shows a spec is wrong or improvable, flag it and flow the change back (`docs/specs/README`);
  don't silently obey it or silently deviate.
- Use `docs/tasks/<task-id>/` for per-task artefacts: `contract.md` (scope), `rubric.md`
  (completion criteria, when risk is medium or high), `verification.md` (evidence, or in the
  PR). `<task-id>` is `NNN-slug` (zero-padded). Templates live in `docs/tasks/_templates/`.
- The lead orchestrates: it plans, judges and synthesizes, and delegates work to the
  subagents in `.claude/agents/` (each description says what the subagent is for) and to
  Codex for review by a second model family. Prompt-bearing work (product prompts, judge
  rubrics, eval criteria) stays with the lead. Start a `general-purpose` agent with
  `model: "opus"` (not Fable, not Sonnet), also when the caller is itself an Opus agent.
  The exception is `/code-review`: its reviewers run on the lead's model.
  Details: `docs/agentic-ops/harness.md`.
- Tests: one focused test for each stated behaviour, at a public boundary (route, public
  function, rendered component, stored row). Mock only what the repository does not own.
  A test never asserts a style class name. Scratch checks are not committed.
- Code, comments, docstrings and test names carry no task numbers, dates, review or polish
  rounds, contract item ids or owner rulings. ADR numbers may stay.
- Deterministic work (date math, parsing, counting, format conversion) runs as a script or
  command, not in latent space — if the same question twice must give the same answer,
  compute it.
- Hard gates: do not change schema, auth, runtime egress (the running product sending
  project data to an outside service), dependencies, CI, production config, public
  interfaces or the project scaffold without approval.
- Never edit generated files or secrets.
- Touch only what the task requires.

# Landmines

Facts about this repository that are easy to get wrong. Delete a line when a test, hook or
command makes it redundant.

- `docs/specs/sources/**` is frozen (ADR 0002): change the spec, not the source. The
  product vocabulary lives in `docs/specs/vocabulary.md`, not under `sources/`.
- `frontend/openapi.json` and `frontend/src/api/gen/types.ts` are generated by
  `make openapi-sync`; `make drift-check` fails on hand edits.
- Prompt text is hash-pinned (`scripts/prompt_hashes.json`, `make prompt-guard`). A prompt
  edit is deliberate slice work: re-pin with `python3 scripts/prompt_hash_guard.py --update`
  and record the diff.
- "Task" has two meanings: the product Task (code row `task`) and "task NNN", an
  engineering slice under `docs/tasks/`. Sweeps must not confuse
  them. Merged task docs and ADRs are never rewritten by later renames.
- `.claude/agents/` holds pinned model routes, not product code; keep it out of codebase
  sweeps.
- `docs/knowledge/` is the verified-facts OKF bundle (`make okf-validate`). Filenames are
  concept ids: do not rename them.
- Codex jobs: `scripts/codex_job.sh wait <job-id>`. Do not write your own status poll: a
  filtered background loop can hide a hard error until it times out.
- Test lanes that share one Postgres database break migration round-trips. `make test` gives each worker its own copy
  (`backend/tests/conftest.py`); a second suite on the same Postgres still needs its own
  `DATABASE_URL` name.
